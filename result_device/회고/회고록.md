# 보고서 - 카카오 약관 기반 성능 개선 대회

## 1일차 내용

### 프로젝트 개요

카카오 약관을 근거로 답변하는 RAG 챗봇의 정확도와 응답 지연시간(latency)을 평가하는 3일 대회에 참가함.

실행 환경은 Google Colab T4 GPU이며, 결과기는 FastAPI 기반 HTTP 서빙 구조로 고정되어 있음. 생성 모델은 Qwen2.5-Instruct 계열을 로컬에서 실행하는 방식으로 진행함.

### 개발 계획

표 1. 개발 단계
| 순서 | 단계 | 내용 |
|---|---|---|
| 1 | 평가 항목별 양식 설계 | 인덱싱, 검색, 증강, 생성 단계별로 baseline과 upgrade를 구분하는 양식을 생성함 |
| 2 | 기법 비교 및 선정 | 양식을 기준으로 임베딩 모델, 검색 방식, 생성 모델 등 후보 기법을 비교해 baseline을 확정함 |
| 3 | 워킹 스켈레톤 구성 | 함수 시그니처와 Pydantic 스키마를 먼저 정의하고, 단계별 스텁 함수로 전체 흐름을 연결함 |
| 4 | baseline 구현 | 스텁 함수를 실제 로직(HTML 파싱, 임베딩, FAISS 저장, LangGraph 오케스트레이션 등)으로 교체함 |

표 2. 사용 스택
| 구분 | 핵심 키워드 |
|---|---|
| 문서 확보 | requests, BeautifulSoup |
| HTML 파싱 | CSS selector 스코핑, TOC(목차) 배제 |
| 조 파싱 및 청킹 | 정규식(제N조), 조 단위 청킹 |
| 임베딩 | bge-m3 |
| 벡터 저장소 | FAISS, cosine top-k |
| 생성 모델 | Qwen2.5-7B-Instruct, 4bit 양자화 |
| 오케스트레이션 | LangGraph |
| 스키마 검증 | Pydantic |
| 초기화 패턴 | bootstrap 멱등성 |
| 자체 채점 | hit@k, key_facts coverage |
| 성능 측정 | p50/p95 latency |

### 트러블슈팅 요약

표 3. 문제 그룹별 요약
| 그룹 | 문제 상황 | 해결 |
|---|---|---|
| 조 파싱 및 청킹 정확도 | 웹 페이지의 목차와 본문에 조 번호가 중복 등장해 조 파싱 로직이 목차 쪽을 채택하면서 실제 조 본문 다수가 소실됨 | 실제 HTML 구조를 확인해 본문 컨테이너(div.wrap_terms.wrap_policy)로 파싱 범위를 스코핑, 목차를 구조적으로 배제함 |
| 결과기 템플릿 통합 | answer_question 함수명과 FastAPI 연결부(app, /health, /answer)가 baseline 코드와 결과기 템플릿 양쪽에 존재해 병합 시 중복 및 역할 충돌이 발생함 | baseline 쪽 함수명을 변경하고, 템플릿의 answer_question 안에서 해당 함수를 호출하는 구조로 정리함. FastAPI 연결부는 템플릿 쪽만 유지함 |
| 초기화 및 리소스 관리 | 인덱싱과 모델 로딩 같은 무거운 초기화가 첫 요청 처리 시간에 포함되어 문항당 타임아웃(120초) 초과 위험이 발생함. 초기화 위치를 최상위로 옮기는 과정에서 이전 실행의 백그라운드 스레드가 GPU 메모리를 계속 점유해 OutOfMemoryError가 발생함 | bootstrap 함수를 셀 최상위에서 1회 호출하도록 분리하고 멱등성(이미 초기화된 경우 즉시 반환)을 추가함. 잔여 GPU 메모리는 Colab 런타임 재시작으로 해제함 |
| Pillow 버전 충돌 | Colab 베이스 이미지에 설치되어 있던 구버전 Pillow가 요구 버전 범위를 형식적으로 만족해 자동 업그레이드되지 않았고, transformers의 이미지 유틸이 요구하는 최신 타입을 지원하지 못해 sentence-transformers import 시점에 오류가 발생함 | 설치 셀에서 다른 패키지보다 먼저 pillow를 강제 업그레이드 및 재설치하도록 순서를 변경함 |
| Colab 커널의 sys.argv 오인 | 파이프라인 실행은 전부 성공했으나, CLI 직접 실행을 전제로 작성된 코드가 Colab 커널이 자기 자신을 기동할 때 자동으로 주입하는 인자를 골드셋 및 제출본 경로로 잘못 해석해 파일을 찾지 못하는 오류가 발생함 | ipykernel 모듈 존재 여부로 노트북 실행과 CLI 실행을 구분하고, 노트북 실행 시에는 sys.argv를 무시한 채 지정 경로에서 파일 패턴을 자동 탐색하도록 수정함 |

### 현재 상태

baseline 구현과 결과기 템플릿 통합을 완료함. 공개 10문항 채점 결과, 검색 단계 10개 모두 정답 도출함.

생성 단계에서 아래 3건의 문제가 확인됨.

- 자기모순 답변: P08에서 정답 근거를 정확히 인용하고도 결론은 "확인할 수 없음"으로 답변함
- 중국어 출력: P10에서 검색은 정답을 찾았으나 최종 답변 전체가 중국어로 출력됨
- 느린 성능 지표: p50 19.6초, p95 39.0초, throughput 0.091 req/s로 스텁 기준 예시(p50 7.0초) 대비 저하됨
